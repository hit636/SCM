# Reproduction contract

## Three separate claims

1. **Execution reproducibility**: install the recorded environment, generate the
   deterministic synthetic fixtures and run the validators. This is verified.
2. **Protocol reproducibility**: use explicit dataset YAMLs and preserve all input,
   cohort, origin, feature, expert, selector, evaluation and configuration hashes.
   The repository provides executable protocols; its public defaults are its own
   documented choices where author records were absent.
3. **Paper numerical reproduction**: use the authors' actual input data and full
   protocol, run all masks/seeds on the required hardware, audit predictions and
   compare measured results against the published tables. This has not been
   established by synthetic checks.

## Author records still required

The supplied manuscript/code do not contain original SNBC data; exact public
cohort manifests and cutoffs; full forecast-origin schedules; all author expert
hyperparameters/checkpoints; the precise rolling-noise margin calculation;
calibration search history/request cap; two-GPU device telemetry; and the complete
inventory input/policy and legacy FAME selector definitions. Obtain these records
before presenting a run as an exact recreation of those experiments. Historical
FAME D1–D3 and all legacy C8 controls are not reconstructed by inventing rules.

## Strict protocol matching

Set `result_kind: paper_reproduction` or `reproduction.strict: true` and supply
`reproduction.author_protocol: path/to/author_protocol.json`. The JSON must contain
the fields generated by `fame_scm.reproduction.protocol_snapshot(cfg, panel)`:
input SHA-256, cohort hash, integer origin lists, target-stage intervals, experts
and forecasting hashes, loss units, data policy hash, selector protocol hash,
evaluation protocol hash, and the shared training seed. Missing or mismatching
fields fail before expert training. An author protocol must come from the actual
author run records; self-generating a matching file only tests the validator.
A matching file binds inputs/settings, not achieved numerical scores or hardware.

## Method choices to report

- Competence labels default to mean per-origin RMSE, not RMSE over all pooled
  targets. Set `scm.competence_loss` explicitly if the author evidence uses another
  definition. Reporting forecast metrics always uses common pooled target weights.
- `acquired_rolling` estimates a frozen margin from paired seed origin losses:
  1.96 × median normalized standard error, with configured fallback if no pair
  has two origins. The margin is frozen before active rounds. This heuristic is
  descriptive; overlapping horizons invalidate an independent-noise interpretation.
- Seed median/MAD normalization uses a training first-difference/lifecycle fallback.
  It is frozen and restored to raw competence-loss units for acquisition/teacher.
- The default teacher tau/eta/nu are fixed; threshold is selected on calibration.
  `calibrate --full-grid` runs an explicit 243-fit engineering grid. It is not the
  original unpublished tuning history. All searches must be predeclared and charged.
- Deep forecasting candidates and their variants use the recorded package APIs;
  the selective SSM is a pure-Torch Mamba-style reference, not upstream CUDA Mamba.
  ST/Gumbel/Sparsemax are documented controls. Exact author implementations were
  not supplied and equivalence is not assumed.
- Measured weighted work uses the full executable mining reference after selection;
  acquisition sees only the frozen training cost profile. Calibration, shared
  preparation, test and hidden audit remain separate. Do not interpret rho as an
  end-to-end savings percentage.
- Bootstrap inference is conditional on fitted models and evidence trajectories.
  Seeds average within masks; paired entity groups × nonoverlapping target-date
  blocks receive the same multiplicities in both methods. Overlapping target
  horizons are not treated as independent runs. No multiple-testing adjustment
  is silently applied.

## Release checklist

Use all five main configs; save the actual realized cohort and origin lists;
predeclare calibration and budget settings; complete five masks × three seeds;
run `audit`, paired comparisons and measured exports; retain execution ledgers,
search logs and shared preparation; collect external GPU utilization intervals
if claiming GPU work; provide the resulting environment, manifests and data access
instructions. Investigate every discrepancy instead of copying paper target values.
